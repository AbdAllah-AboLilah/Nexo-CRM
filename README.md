**الإصدار:** v2.0.0

## أول تشغيل (مرة واحدة بس)

### 1. حساب منشئ النظام
من Firebase Console ← **Authentication ← Users ← Add user**:

```
admin@nexo.com   +   كلمة مرور قوية
```

> الإيميل ده معرّف في `js/config.js` وفي `firestore.rules`. لو غيّرته، غيّره في المكانين.
> أول ما تدخل بيه، النظام بينشئ حسابك كـ Super Admin تلقائياً.

### 2. المفاتيح السرية

```bash
firebase functions:secrets:set GEMINI_API_KEY
```

```bash
firebase functions:secrets:set TOKEN_ENC_KEY
```

```bash
firebase functions:secrets:set META_VERIFY_TOKEN
```

```bash
firebase functions:secrets:set META_APP_SECRET
```

| المفتاح | من فين | مطلوب دلوقتي؟ |
|---|---|---|
| `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com/app/apikey) — لازم يبدأ بـ `AIza` | ✅ |
| `TOKEN_ENC_KEY` | أي نص عشوائي طويل تخترعه (بيشفّر توكنات المنصات) | ✅ |
| `META_VERIFY_TOKEN` | أي كلمة سر تخترعها وتحطها في إعدادات ميتا | لاحقاً |
| `META_APP_SECRET` | من Meta App ← Settings ← Basic | لاحقاً |

### 3. الرفع

```bash
firebase deploy
```

## إضافة شركة جديدة (لما تتعاقد مع عميل)

1. **إدارة الشركات ← إضافة شركة جديدة** — اسم الشركة والنشاط والباقة.
2. **زرار ⚙️ الميزات** — افتح المنصات والميزات المسموحة لباقته وحدد عدد المستخدمين.
3. **زرار «دخول»** — تدخل على لوحة الشركة.
4. **المستخدمين ← إضافة مستخدم** — اعمل حساب صاحب المكان (Owner) وسلّمه الإيميل والباسورد.
5. **الثوابت** — العنوان، المواعيد، الأرقام، سياسة الاستبدال، وروابط التواصل.
6. **الذكاء الاصطناعي** — النبرة وشخصية البوت.
7. **المخزون** — استيراد ملف الأصناف والأسعار.
8. **ربط المنصات** — تليجرام بيشتغل فوراً؛ الباقي محتاج موافقات ميتا.

> **مهم:** أنت مش بتاخد ولا بتسجّل كلمة سر فيسبوك من أي عميل نهائياً. الربط بيتم بـ OAuth من ميتا نفسها.

## الأدوار والصلاحيات

| الدور | بيشوف إيه |
|---|---|
| **منشئ النظام** | كل الشركات + الميزات + الإصدارات + الدخول كأي شركة |
| **صاحب المكان** | التقارير والتحليلات والمستخدمين وربط المنصات والثوابت |
| **مدير السوشيال ميديا** | المنتجات والنشر والجدولة وإعدادات الرد الآلي والطلبات |
| **موظف خدمة عملاء** | صندوق الرسائل فقط |

الصلاحيات متطبّقة في مكانين: القائمة الجانبية (شكلي) و`firestore.rules` (الحماية الحقيقية).

## ملف استيراد الأصناف

الأعمدة اللي النظام بيدوّر عليها (عربي أو إنجليزي):

| العمود | بدائل مقبولة |
|---|---|
| اسم الصنف | الصنف / المنتج / name / product |
| القسم الرئيسي | main category / category |
| القسم الفرعي | sub category |
| السعر قبل الخصم | price before |
| السعر بعد الخصم | سعر البيع / price after |

الاستيراد المتكرر **بيحدّث** الأسعار ومش بيكرر الأصناف (المعرّف مبني على اسم الصنف).

## حالة المنصات

| المنصة | الحالة | المطلوب |
|---|---|---|
| تليجرام | ✅ شغال | توكن من @BotFather |
| فيسبوك | ⏳ الكود جاهز | App Review + Business Verification |
| انستجرام | ⏳ الكود جاهز | نفس موافقة ميتا + حساب Professional |
| واتساب | ⏳ | Cloud API + قوالب معتمدة (مدفوعة) |
| جروبات فيسبوك | ❌ | ميتا قفلت الـ API |

**قيود لازم تعرفها:** الرد الخاص على تعليق مسموح **مرة واحدة** لكل تعليق وخلال 7 أيام.
واتساب: الرد مسموح خلال **24 ساعة** من آخر رسالة من العميل، وبعدها لازم قالب معتمد ومدفوع.

## التحديث من الموبايل

بعد ما تضيف `FIREBASE_SERVICE_ACCOUNT` في GitHub ← Settings ← Secrets:
أي تعديل تعمله من موقع GitHub على الموبايل بيترفع أوتوماتيك على فايربيز.

لتوليد المفتاح: Firebase Console ← ⚙️ Project settings ← Service accounts ← Generate new private key،
والصق محتوى ملف الـ JSON كله في الـ Secret.

## ملاحظات أمنية

- توكنات المنصات مشفّرة (AES-256-GCM) ومخزّنة في `companies/{id}/secrets` — **العميل مايقدرش يقراها من المتصفح إطلاقاً**.
- ويب هوك ميتا بيتحقق من التوقيع `X-Hub-Signature-256`.
- ويب هوك تليجرام بيتحقق من `X-Telegram-Bot-Api-Secret-Token`.
- إنشاء الحسابات بيتم من السيرفر بس (Admin SDK) مع فحص حدود الباقة.
- `firebase.json` مضبوط إن `functions/` مش بيترفع مع ملفات الموقع.
